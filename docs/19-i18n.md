# 19 — Internationalization

## Two layers (do not mix them)

| Layer | What it translates | Example | Status |
|-------|-------------------|---------|--------|
| **UI i18n** | Chrome, buttons, nav, system messages | “Save”, “Users” | **Shipped** — module JSON + API |
| **Translatable fields** | Business text per record | Company name per locale | **Planned** — `base_translation` |

## Canonical source (English core)

All UI message keys are owned by **`modules/base/i18n/en.json`** (English only).
Additional locales ship in **optional modules** (reference: `modules/locales` for
`pl`, `de`, `fr`). `scripts/check_i18n.py` keeps locale JSON aligned with `en.json`.

Product modules add **`modules/<name>/i18n/<lang>.json`** and list languages in
manifest `i18n`. Register the module in `backend/api.py`. See
`backend/modules/base/i18n/README.md`.

## Merge order (later wins)

1. `modules/base/i18n/en.json` (canonical; fallback for missing keys in other locales)
2. Other modules’ `i18n/{lang}.json` (registry load order)
3. `base.ui-translation` rows (operations / per-tenant overrides)

## API (SPA)

| Endpoint | Purpose |
|----------|---------|
| `GET /api/base/i18n/locales` | Language picker metadata (`source`: `core` \| `module`, `module` slug) |
| `GET /api/base/i18n/messages/{lang}` | Full merged catalog |

Authenticated admin shell fetches the full catalog once (React Query,
5 min `staleTime`, no refetch on window focus). **`/login` and `/welcome` do not
call the messages API** — they use `PUBLIC_PAGE_FALLBACK_EN` (~130 keys) synced
from `en.json` via `scripts/sync_public_i18n_fallbacks.py`. Root layout does
**not** server-fetch i18n (avoids blocking every Next.js request on ~32 KB).

Portal uses the same static bootstrap until the API catalog loads
(`waitForCatalog={false}`).

Locales from a **disabled** module (Module catalog toggle) are omitted from
`/i18n/locales`; message requests for those codes fall back to `en`.

Admin UI: toggling a module calls `applyModuleToggleSideEffects()` (see
`docs/03-modules.md` § Enable / disable) — includes i18n cache bust among other
query prefixes. The shell keeps the previous catalog visible during refetch
(no full-screen loader on `isFetching`).

Performance: `load_enabled_map` is cached (~5s TTL, one config query); merged
message catalogs are cached in memory per locale + module-enable signature.

## Locale negotiation

1. Authenticated `user.language` (`GET /api/auth/me`)
2. Guest: `localStorage` `orbiteus.locale`
3. Fallback: `en`

## Frontend

- **`@orbiteus/i18n`** — `I18nProvider`, `useT()`, `waitForCatalog`, merge helpers.
- **No** full catalogs in `packages/i18n` (only route keys in `nav.ts` for helpers).
- New UI strings: edit `modules/base/i18n/en.json`, mirror in locale modules, use `useT("key")`.

## Adding a module language pack

```python
# manifest.py
"i18n": ["en", "pl"],
```

```json
// modules/inventory/i18n/pl.json
{ "inventory.list.title": "Stan magazynowy" }
```

## Database overrides

Model `base.ui-translation`: `lang`, `module`, `msg_key`, `value`.

## Translatable fields (future)

Opt-in per field; table `base_translation` — not part of UI i18n.

